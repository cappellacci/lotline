- **Question:** Do Oregon's national inputs (BPS, ACS, FHFA, FRED, demand, jurisdictions, eligible lots) build with every outcome from 2018 on hidden (V9-OR-TRANSFER)?
- **What I did:** After #287 (BPS West Region, ACS stock filter, state-total filter) merged, Claude Code ran `lotline fetch --state OR` on main at fbdfbb3. It then checked each processed table's year ranges and non-null counts, never values. ACS stock variables (B25024, B25034, B25003) stop at end year 2017, and rent and value run to 2024. Eligible lots are the ACS fallback, 2010–2017 only. Jurisdictions: 168 (136 places, 32 county remainders, all tier 3).
- **Incident:** `processed/or/bps_place_year/bps.parquet` held **8 rows from 2018 on with a null GEOID, carrying 96 non-null permit-count cells**. The statewide prefix match in `validation/holdout.py` (`str.startswith(...).fillna(False)`) never held out a null GEOID. Only row and non-null cell counts were read; no values, names or years beyond the count were looked at. Reported to the coordinating session at once; WS-CORE fixes it in #288 (a statewide holdout treats a null GEOID as inside the state, with a test). The file was left untouched until the rebuild (`--source bps`, then `jurisdictions`, then `eligible`) overwrites it; nothing built from it was used.
- **Inputs:** main at fbdfbb3; `config/states/or.yaml` holdout V9-OR-TRANSFER.
