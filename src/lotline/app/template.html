Lotline

Lotline is a tool to help understand how much new housing specific housing reforms would add. It learns from places in the country where these reforms have passed, takes each state's housing market and local factors into account, and estimates what a reform would add over five years, as a range.

    The data

    What data powers our model

    The time line. The model learns from permits through 2025, the last full year of data, and forecasts the five years 2027–2031, when a reform passed in 2027 could act. 2026 falls in between and is not reported. A few places' most recent years are hidden from the model so its forecasts for them can be tested blind.

    Add a state

    Lotline runs for any U.S. state. National data already covers every state, so a new state can have first results in an afternoon, and each local source you add narrows its ranges. This guide takes you from a fresh copy of Lotline to your state on the map.

    What you need

    • A computer with uv (it installs the right Python for you) and git.
    • A free Census API key.
    • About an hour for the national data to download.
    • Optional: Claude Code with your own account, if you want the rule agents to research local rules for you (step 5).

    Choose how far to go

    1

    Set up Lotline 15 minutes

    Everything runs on your own computer, from your own copy of the code.

    Copy Lotline and install it:

    git clone __REPO_URL__
cd lotline
uv sync --frozen
cp .env.example .env

    Open .env and add your CENSUS_API_KEY. Downloads go to LOTLINE_DATA_DIR (by default ~/lotline-data), outside the code, so no data is ever mixed into it.

    2

    Write your state's settings file 15 minutes

    One short file is all the engine needs to know about a state; nothing else in the code changes.

    Create config/states/xx.yaml (your state's two-letter code in lower case). Copying config/states/oh.yaml is the quickest start:

    state: XX                  # two capital letters, matching the file name
name: Statename
fips: "55"                 # the state's two-digit FIPS code, in quotes
bps_region: Midwest Region # Northeast, Midwest, South or West Region
township_permits: false    # true where townships issue building permits
zip3_ranges: [[530, 549]]  # the state's 3-digit ZIP prefixes
holdouts: []
sources: []

    Saving the file adds the state everywhere, including this app. The loader rejects any setting it does not know, so a typo fails loudly.

    3

    Fetch the national data about an hour, mostly waiting

    Census permits, housing counts, home prices, rents, interest rates and building costs exist for every state, so the model can run before you gather anything local.

    uv run lotline fetch --state XX
uv run lotline validate --state XX
uv run lotline fetch --source jurisdictions

    The first command downloads and builds every table the models read, and records each file it fetched. The second checks that the Census place-by-place permits add up to the state total within 1% and writes a short report to reports/xx/V0-national.md. The third builds the place lists of the five study states, because a new state borrows their coded rules until it has its own.

    4

    Run the models a few minutes

    This gives you level 0: a first set of results for all three reforms, with the widest ranges.

    uv run lotline results --state XX
uv run python scripts/build_app.py

    The first command runs the ADU, missing-middle and fee models 1,000 times each and writes reports/results/xx/bundle.json. The second rebuilds this app: open reports/app/index.html and your state is on the map, labelled "National data only".

    5

    Code local rules and fees level 1

    The model needs to know what each city allows today, or it can't tell what a state reform would add; this is the step that makes ADU results trustworthy.

    With the rule agents

    Open Claude Code in the Lotline folder and type one command per kind of rule. Start with the largest 10 places:

    /rules-adu XX --limit 10
/rules-mm XX --limit 10
/rules-fees XX --limit 10

    The agents find each place's official documents, code every value with a word-for-word quote, and hand you a proposed table plus a short list of lookups they could not reach. Fill in the lookups you can, then preview and import:

    uv run python -m lotline.rule_agents import <run folder>/out/<proposed>.csv reforms XX
uv run python -m lotline.rule_agents import <run folder>/out/<proposed>.csv reforms XX --yes

    The first shows what would change; nothing is written until you add --yes. Guide: Adding local rules with the rule agents.

    By hand

    Rules go in config/reforms/xx.csv (copy the header from config/reforms/or.csv). Start with the state law, if there is one, then the 20 largest places, then any other place that changed its rules in the last ten years. Record a place that does not allow ADUs too, with adus_per_lot set to 0: a missing place counts as unknown, and the model borrows a rule from similar places.

    Fees go in config/fees/xx.csv. Take about six of the largest places and copy from each official fee schedule the water and sewer connection fee, impact fees, and the building permit and plan review fees, for a house, an ADU, a duplex and a three- or four-unit building. Five places is the minimum for the state to get its own typical fee. Guide: how to code fees.

    Then run step 4 again.

    6

    Add local permits and parcels levels 2 and 3, optional

    Local records replace national estimates with real counts, which narrows the ranges most.

    Each local file plugs in through a small adapter in src/lotline/adapters/states/xx/ that turns it into the same table every state uses; src/lotline/adapters/states/or/rlis_parcels.py is the template for parcels. Every adapter comes with a test on a few made-up rows, never on downloaded data. Then rebuild the tables that read local data, in this order, and rerun the models as a "transfer" state (one the model was not fitted on):

    uv run lotline unlisted --state XX
uv run lotline fetch --state XX --source jurisdictions
uv run lotline fetch --state XX --source eligible
uv run lotline fetch --state XX --source demand
uv run lotline fetch --state XX --source place_inputs
uv run lotline results --state XX --role transfer

    7

    Read the results before you share them half an hour

    A range is only useful if you know how far to trust it, and a new state is where the model reaches furthest.

    • Is the state like the places the model learned from? The Model tab (step 5b) shows a plain verdict: inside, near the edge or outside the evidence. Outside means read the ranges as rough, and say so wherever you quote a number.
    • The data tier and caveats on the Results page say what the numbers rest on.
    • ADU ranges are wider for a state outside the fit, because the model draws how different an unknown state might be. That is intended.
    • Places with no Census rent or home value are left out of the results. Count them before quoting a state total.
    • Fees: check how many places use their own coded fees and how many borrow the state's typical fee.

    Going further

    Test the model blind. To predict your state before seeing its recent building, as we did for Oregon, add a holdout to the settings file before the first fetch. It is optional; the full guide explains how.

    Share your state back. To add it to the public Lotline, open a pull request with the files from steps 2, 5 and 6. The full guide lists the checks it must pass.

    The model

    Lawmakers need to know how many homes a reform would add, and how sure they can be. Our model gives an expected range of outcomes for each policy and shows its uncertainty. We checked it against what actually happened in places we held back from the model. Only a handful of places have passed these reforms, and homebuilding rises and falls for many other reasons, so we had to control for many factors to get an honest range. We built the method so that any state could get an honest answer from its own data.

    1

    The goal: exactly what we measure

    The question. If a state passed one of three reforms, how many more homes would it gain over the five years 2027–2031 than under the rules already in place? The headline counts net new housing: homes finished, minus houses torn down to build them and homes that would have been built elsewhere in the state anyway.

    The reforms, the comparison, the unit and the ranges

    The three reforms follow the Challenge Handbook to the letter. The ADU reform allows one backyard home per house, at least 600 sq ft, with no parking required. Missing middle allows 2–6 homes, up to three stories, on lots now zoned for one house. The fee reform cuts development fees in half, and we show it two ways: the Challenge benchmark, which assumes a $50,000 fee everywhere and cuts it to $25,000, and each city's real fees cut in half.

    We always compare a reform with no reform. "No reform" keeps every city's own rules, including laws already passed that take effect by the end of 2027, so a reform is never credited with homes that current law will produce anyway.

    We count homes in building permits and add them up place by place to a state total. That total gives two numbers. All new homes are permits that get finished and add a home someone can live in. Net new housing is all new homes minus those that would have been built elsewhere in the state anyway; that share is a quarter by default, and anywhere from none to half.

    Every answer is a range. The model runs 1,000 times, each time with different plausible values for everything it is unsure about, and the page shows the middle 80% of those runs (P10 to P90) and the midpoint.

    2

    Preparing the data

    For every city, town and township in every year, the model needs two counts: how many lots a reform could touch, and how many homes were permitted. The Data page lists every source. Click below to see the rules we applied to them:

    How we prepared each kind of data

    Lots the reform could touch follow one written rule, applied the same way in every state: for ADUs, a lot with one single-family house; for missing middle, a lot zoned for single-family homes only that holds one house or is vacant. Where a place has no parcel records, Census counts of single-family homes stand in. We tested that stand-in against real parcel counts in all five states and it came within 8% everywhere (0.92 to 1.07 times the parcel count); for missing middle it runs about 12% low, a known gap.

    Homes permitted come from Census permit counts by building size (1, 2, 3–4 and 5+ homes) for every place since 1992, plus city permit files that mark ADUs. A project total repeated on several permits is counted once.

    Local rules carry dates. For each city we looked up when it allowed ADUs or missing middle and how strict the rule is: whether it is by right, whether the owner must live there, and its parking and size limits. Places nobody has coded borrow the rules of similar coded places of the same size.

    Unknown is never zero. A missing year stays missing rather than counting as a year with no building, and an unknown zoning code counts the lot as eligible, flagged as an assumption.

    Some years were hidden for blind tests. We locked away some places' recent records so we could predict them first and look later. Oregon's records from 2018 were predicted from the other four states, then opened on November 5 and added to the fit. Charlotte's from mid-2023, including the county figures its permits are filed under, were predicted and then opened on November 9. St. Paul's from 2024 stayed locked until its frozen prediction was scored on 16 November 2026.

    Each state has a data tier that says what its data rests on: tier 1 is local parcels with year built, tier 2 is local parcels with land use, and tier 3 is national data only.

    Causal factors and confounders

    Homebuilding rises and falls for many reasons besides law reforms. Before fitting anything, we mapped these reasons so the model only credits a reform and not other effects. We drew them from our own design work and a review of 114 published studies and reports on ADU, zoning and fee reforms.

    3c. What gets built anyway

    A reform only gets credit for homes beyond what each place would build anyway, so we forecast that first.

    Each place keeps its own recent pace: homes permitted per 1,000 eligible lots over 2021–2025. Small places with lumpy records are pulled toward their county's pace. On top of that runs the state's building cycle. The model replays year-to-year swings drawn from the state's last 25 years, so some runs see a boom and others a bust. This baseline is what every reform is measured against.

    Building the models

    With the confounders mapped, we built each reform's effect from parts we can measure, gave every answer a range, and tested the model before trusting it.

    4a. Why we built each effect from its parts

    We can't measure a reform's potential from historical data alone, so we build it from three parts we can measure.

    Lots where the reform allows something today's local rule does not. A city that already allows ADUs gains few.

    =

    Extra homes

    The homes the reform adds on top of what gets built anyway.

    Why not just compare reformed cities with similar ones?

    That was our first plan. In the four states we first studied (before Oregon was added), those comparisons could not tell a real effect from noise: they could only have detected effects many times larger than any plausible one, and a placebo check failed (see 4d). Building the effect from measured parts avoids that problem. Fee cuts are the one part we could not measure ourselves: no place in our states cut fees on the scale of the reform, so their response comes from published studies (see the fee card).

    4b. Deep dive into our models

    Each reform changes building in a different way, so each has its own model designed around the same principles.

    What the model does

    Every house lot where an ADU is allowed has a small chance each year of getting one. That chance depends on how strict the city's rules are and whether it is a big city, a suburb or a town. The reform raises the chance most where local rules are stricter than the reform, for example by requiring parking or an owner on site.

    How it works

    ADUs a year = lots where allowed × base chance × how much the local rule allows × big-city factor × place's own luck

    How each part is measured
    • Base chance: about 2 lots in 10,000 a year get an ADU in a suburb whose rules match the reform (0.22 per 1,000 lots; 0.17 to 0.30).
    • Local rules: a rule whose only extra condition is that the owner lives there gets the full chance. A rule with other limits (a parking space, a smaller size cap, a permit hearing) reaches about 70% of it. That share is uncertain, so each run draws it, from 40% to 100%.
    • Big cities and suburbs. Each place gets one of three labels, from national census data only:
      • core city: the biggest city in its metro area, or one at least a third its size;
      • suburb: any other place in a metro area;
      • town: a place outside any metro area.
      Core cities build ADUs at about 6 times the rate of suburbs with the same rules (3 to 11 times). This one fact explains much of the gap between states.
    • Place's own luck. Some places build more or fewer ADUs than their rules suggest, for reasons we can't see: local builders, prices, habits. The model does not guess why; it gives each place a multiplier drawn to match how much real places differ. This is a large part of why answers come as ranges.
    • Prices and borrowing. The chance rises where an ADU's rent covers what it costs to build, and with homeowners' equity; it falls as mortgage rates rise, because most ADUs are built by owners who borrow against their house. The sizes of these effects are judgment calls with wide ranges.
    • Places that count their own ADUs keep their own recent pace as the no-reform rate. The reform adds the gap between what today's rule allows and what the reform allows. A place that allows no ADUs today gets the full rate for its type.
    What it learned from
    • Counted ADUs: city permit files that mark ADUs, in places across Minnesota, North Carolina, Texas, Oregon and Ohio.
    • Checked local rules: for 70 places we went back through their ordinances year by year and recorded their ADU rules from 2016 to 2025, then checked those records against the original sources. The fit uses 498 place-years.
    • Tested and set aside: a slower start in the first years after a city first allows ADUs. The data leaned that way, but it did not predict held-out places any better, so it was not used.
    How we tested it

    Pass

    We hid one state, fitted the model on the others and predicted the hidden state from two things only: its places' types and the coded rules of its 20 largest places. A prediction counted as useful if the actual number fell inside its range (P10 to P90) and the midpoint was within a factor of two.

    Useful in all four. Ohio could not be tested this way: only 3 of its places have usable ADU counts. These four states also shaped the model's design, so this is not a fully blind test. The blind one, Oregon predicted before any of its data was opened, missed low (see the tests table below).

    What the model does

    Every lot zoned for one house that the reform opens to 2–4 homes has a small chance each year of getting a small multi-unit building, on top of what the place already builds. That chance is higher where rents cover the cost of building, and it grows slowly: it reaches half its full size after about four years.

    How it works

    2–4 unit buildings a year = the place's usual pace + mature rate × eligible lots × how much the rule changed × whether building pays × how far in the reform is

    How each part is measured
    • The usual pace is the place's own 2–4 unit building in the 3 years before the reform, moved with its growth in other homes.
    • The mature rate: about 1 new 2–4 unit building per 1,000 eligible lots a year once the reform is fully in effect where building just pays. Its range is very wide (0.13 to 19 per 1,000).
    • How far in the reform is: the effect builds up over time, reaching half its full size after about 4 years (1 to 6), as in Oregon's places that the state law required to allow it. By the fifth year it is still growing.
    • Lumpy years: a third or more of these buildings come in projects of three or more, so a place's count swings with whether one large project lands in the window.
    • What it counts: Census permits for 2–4 unit buildings, the only size reported the same way everywhere. The reform allows up to 6, so this is a floor.
    What it learned from
    • 93 places in all five states (86 of them in Oregon, most under its 2019 law, HB 2001) whose coded rule raised the number of homes allowed, or how easily they are approved, between 2013 and 2025.
    • Places that always allowed missing middle, to anchor the mature rate (widened, because such places may differ).
    • 483 other places, used only to measure how lumpy a place's years are.
    • Tested and not used: place types (they did not narrow the ranges).
    How we tested it

    Partial

    • Single places: 78% of 136 places landed inside their range (the target was 60% to 95%).
    • A new state: with Oregon left out, the other states predicted 457 to 4,789 buildings in Oregon's places (midpoint 915); 703 were built.
    • Blind: Charlotte passed, with the earlier values. St. Paul, frozen with these values before any result was read, missed: 55 buildings in 2024–2025 against a range of 9 to 28. It built 33 in its first full year, against about 6 a year before.
    • The weak spot: the reform's own effect is not clearly detected. The model with a reform effect beats the same model without one by only about 1.5 standard errors, short of the 2 we set as the bar, and a fake reform date three years early shows a larger effect than the real dates.

    What the model does

    Cutting the fees a builder pays the city lowers the cost of every new house, duplex and fourplex. About half of the saving ends up in land prices, so builders keep the rest. Building then rises a little above its usual pace: a 10% cut in cost adds about 3% more homes.

    How it works

    extra homes = usual homes × how strongly building responds × builder's share of the cut ÷ total cost of the home

    How each part is measured
    • The cut, shown two ways on the Results page: the Challenge benchmark, $25,000 a home (half of a $50,000 fee assumed everywhere), and half of each city's real fees for houses, duplexes and fourplexes. Buildings of 5 or more homes are never covered.
    • Builder's share: about half of a fee cut ends up in land prices, so builders keep the other half (a quarter to three quarters).
    • How strongly building responds: a 10% cut in cost raises building by about 3% (Baum-Snow and Han 2024, measured neighborhood by neighborhood), from almost none (Mayer and Somerville 2000; Campbell and Alm 2006) to 17% (the metro-wide response in Saiz 2010 and Aastveit and others 2020). Each run draws one value.
    • Lots that newly pay are not counted. The cost model can count lots that start to pay after the cut, but only where a city has parcel data, and it gave answers many times larger than the rule above. So every place uses the same rule.
    What it learned from
    • Fee schedules coded for 58 places, which hold about a third of each state's usual building. Other places take their state's median fee ($3,900 a home in Texas to $9,100 in Minnesota).
    • How strongly building responds comes from published studies, not our own places: most studies of fees find no clear effect on how much is built, and the high end comes from metro-wide supply studies.
    How we tested it

    Not yet run

    The fee model is built and checked against hand-worked examples, but it has not been tested against what happened after a real fee change. Its results are on the Results page as a range, like the others.

    What it can't tell you
    • How a city replaces the money. Fees often pay for roads, pipes and parks; what happens to those is not modelled.
    • Its own accuracy. Unlike the other two models, its key number is borrowed, not measured here.
    • Oregon: only 4 cities are coded (Bend, Eugene, Portland and Salem), with fees far above the other states' ($17,500 to $42,800 a home, mostly system development charges). Four is too few for an Oregon median, so its other places take the median of every coded place (about $7,100), which likely understates what they charge.
    Sources

    Sources: docs/analysis_plan.md D-010, D-065, D-073, D-076, D-077; config/params/fees.yaml.

    4c. How we get a range: runs and probabilities

    No single number would be honest, so every answer is the middle 80% of 1,000 runs that each draw different plausible values.

    Many of the model's inputs can't be known exactly: how often owners will build, how strong the next building cycle will be, how much one city differs from the next. So the model does not run once. It runs 1,000 times, and each run picks a different plausible value for each uncertain input, from the range the evidence supports. Every run gives one answer. The chart lines up all 1,000 answers from lowest to highest.

    The midpoint

    Half the runs came out below it and half above. It is our best single guess, not a promise.

    The range (P10 to P90)

    The middle 80% of runs. 1 run in 10 came out below it and 1 in 10 above, so 1 in 5 lands outside it.

    A wide range

    Means the evidence leaves a lot unsettled, not that the model failed. Missing middle's ranges are the widest for that reason.

    The log scale

    Runs bunch up at the low end and trail off far to the right. On a log scale each step is ten times the last, so both ends stay readable.

    Every source of the range

    Each of the model's runs differs in six ways. It replays a different stretch of the state's past booms and busts. It draws how often owners build, and how fast, from their fitted ranges instead of fixing them at one value. For ADUs, it draws how much a partial local rule already allows from the values the data support.

    It gives each place its own multiplier for the differences we cannot measure, drawn to match how much real places differ, with a wider spread still for a state the model was not fitted on. It draws the judgment calls (finished homes per permit, homes that would have been built elsewhere, and conversions of existing units) from stated low-to-high ranges, each with a source in config/params. And even at a known rate, the count in any one year varies by chance.

    5b. Adding a new state

    Every state already has the national data the model needs, so a new state can run on day one and gets sharper with each local source it adds.

    The engine keeps the method apart from the data. A state is a settings file; its local files plug in through small adapters that turn them into the same tables every state uses, and the model's equations never change. National data (Census permits and housing counts, home prices, interest rates and building costs) is fetched automatically for every state.

    What a new state needs, and what happens with little data

    A new state supplies its Census code and whatever local data it has: parcel rolls, city permit files, coded local rules and fee schedules. Everything national (Census permits, housing counts, prices and rates) is fetched automatically.

    With little local data, the model still runs. Lots come from Census housing counts, adjusted using the stand-in test above, and uncoded places borrow rules from similar coded places. The state's unknown character gets the widest spread the model has, anywhere from a third of a typical state to three times one. ADU place types come from national data, so every place in any state gets one, even in a state with no ADU counts at all. Places outside a state ADU law borrow the rules of small towns in states without one, not those of big cities that have reformed.

    Oregon is the test case. It was predicted from the other four states before its own results were looked at, and the app shows it as the "transfer" state. Its missing-middle results were not used to fit the model; since 2026-11-06, Portland and Bend are part of the ADU fit.

    5c. Coding local rules with rule agents

    Local rules and fees are the slowest data to gather by hand, so we built AI agents that research them and show their evidence.

    For a new state, the rule agents look up each place's ADU rules, missing-middle rules and development fees. Place by place, they find the official documents (the current code, the ordinance that changed it, the fee schedule), code each value with a word-for-word quote and the page it came from, and check every quote against the stored document by machine. On the places that matter most, a second agent codes the same place without seeing the first one's work, and a third settles any disagreement. They respect every site's rules for automated visitors and never contact anyone.

    They propose; a person decides. Each run produces a table in the app's own format, a short list of lookups the agents could not reach (most important first, with the link and what to look for), and a plain report of what was found and how sure it is. Nothing changes in the app until someone reviews the table and imports it. Anyone can run them with their own Claude account. The guide is Adding local rules with the rule agents.

    What the model cannot tell you

    • Single cities are very uncertain. The state total is the number to rely on; one city's range can be very wide.
    • Missing middle's effect is not clearly detected: its edge over "no effect" is about 1.5 standard errors, short of the 2 we set as the bar, so its range is very wide.
    • High-uptake ADU markets can be under-predicted, as Portland and Bend were in the blind test.
    • Not modelled:
      • how two reforms interact on the same lot: each reform is run on its own;
      • 5–6 unit buildings, which Census permits lump with larger ones;
      • height and floor-area limits;
      • approval times;
      • what happens to prices, rents, or who lives in the new homes.
    • Fee cuts are not tested against a real fee change, and their key number (how strongly building responds) is borrowed from published studies.
