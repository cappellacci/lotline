# North Carolina model run, 2026-10-22

> **DEVELOPMENT RUN. Not a result.** These numbers check that the models run end to end on North Carolina's
> data. They are not published estimates and should not be quoted as Lotline findings.

**Question:** with North Carolina's data finished (PRs #199–#202, #204, #206, #207, #210), do the models run
statewide, and what do they say?

**Short answer:** everything ran with no crashes or warnings. The baseline backtest passes 2 of 12 test cells
(unchanged). The ADU scenario adds about **2,100 ADU permits over five years statewide (P10 570, P90 7,000)**,
which is about **1,100 more homes** once ADUs that replace other building are netted out. Almost every NC place
(447 of 450) has no coded ADU rule, so the model draws one (D-022), and 440 of 450 places sit outside the range
the ADU model was calibrated on. Read the ADU numbers as very uncertain. The fee scenario covers only Raleigh,
the one NC place with coded fees.

Data: processed NC tables in `LOTLINE_DATA_DIR` as rebuilt for today's merges (48-county OneMap parcels, Wake
2019 + 2023 rolls, Greensboro / Durham / Raleigh / Mecklenburg permits, eligible parcels with ACS-scaled history).
Code: `origin/main` at `e6b8662` (includes the fee scenario, #189). Origin year 2025; forecast years 2026–2030.
The holdout filter was left on: Charlotte (3712000) and Mecklenburg County (37119) outcomes from 2023-06-01 are
not in any table used here.

## 1. Baseline backtest (V1, spec B)

`uv run python -m lotline.model.backtest --state NC --spec B` (defaults: eligible-parcel theme `adu`, current
eligibility rule, county shrinkage). The model fits on years up to 2016, 2018 or 2020 and forecasts the next
five; it "passes" a cell if it beats both simple benchmarks, its 80% ranges cover enough outcomes, and its mean
is not biased after 2022 (D-003 to D-005). These windows are the development set (D-029).

Error is mean absolute error in permits per place per year.

| Fit ends | Size class | Model error | 3-yr mean error | Trend error | Beats both | Coverage (80% range) | Bias OK | **Pass** |
|---|---|---:|---:|---:|---|---:|---|---|
| 2016 | 1 unit | 9.89 | 9.47 | 11.18 | no | 0.57 | yes | no |
| 2016 | 2 units | 0.369 | 0.460 | 0.467 | yes | 0.88 | yes | **yes** |
| 2016 | 3–4 units | 0.099 | 0.132 | 0.163 | yes | 0.95 | yes | **yes** |
| 2016 | 5+ units | 3.39 | 3.44 | 3.95 | yes | 0.72 | yes | no |
| 2018 | 1 unit | 11.81 | 11.69 | 12.30 | no | 0.55 | no | no |
| 2018 | 2 units | 0.365 | 0.488 | 0.615 | yes | 0.88 | no | no |
| 2018 | 3–4 units | 0.092 | 0.152 | 0.178 | yes | 0.96 | no | no |
| 2018 | 5+ units | 4.17 | 4.28 | 4.77 | yes | 0.74 | no | no |
| 2020 | 1 unit | 13.09 | 12.80 | 13.06 | no | 0.53 | no | no |
| 2020 | 2 units | 0.378 | 0.503 | 0.598 | yes | 0.87 | no | no |

**2 of 12 cells pass**, the same as the last NC figure on record (D-012 re-run note, 2026-10-20: NC 2 of 12,
from a four-state run), and the same two cells pass in both (2016 fit, 2 and 3–4 units). That note gives MAE
only for all four states together, so a like-for-like NC MAE comparison isn't possible from the docs. NC model
MAE averaged over the three windows: 11.60 / 0.371 / 0.097 / 3.89 for 1 / 2 / 3–4 / 5+ units. The 2016 fit has
no post-2022 years, so its bias test is not applied.

What the table shows:

- **Single-family homes fail in every window.** The model does no better than the 3-year average, its 80%
  ranges catch only 53–57% of outcomes, and after 2022 it under-forecasts (bias of the mean −7.1 and −5.1
  permits per place per year for the 2018 and 2020 fits). This is the same NC pattern D-007 recorded.
- **2–4 unit buildings are the model's strength:** it beats both benchmarks in every window, with good coverage.
  They fail only on the post-2022 bias test.
- **5+ unit buildings** beat the benchmarks but have narrow ranges (72–75% coverage).
- **Statewide totals** (reported, not a pass test): the model under-forecasts the five-year state total in 11
  of 12 cells: by 14–23% for single-family homes and 24–44% for 5+ units (2018 3–4 units is 13% over).

How to read this: where a city's current rule already matches the Handbook (Greensboro), the reform adds
nothing. Where it is close but some fields are uncoded (Charlotte, Raleigh, Durham, Winston-Salem), the model
draws between "already Handbook" and "partial"; the P50 is 0 and the mean comes from the draws where the city is
"partial". Charlotte's and Raleigh's P50 of 0 with a P90 in the hundreds is that split, not a data error.

**Unknown rules (D-022):** the rule is drawn for **447 of 450 places (97% of eligible parcels)**. 425 places have
no coded rule at all and 21 are coded as uncertain; only 4 (2 none, 1 partial, 1 Handbook) are fixed. Over the
drawn places the draws average 22% "no ADUs allowed", 66% "partial", 12% "Handbook".

**Outside the calibration range:** **440 of 450 places.** The median place is 1.26 units of calibration distance
outside (max 3.77). The ADU effect for nearly all of NC is extrapolated (D-025's wide intervals apply in full).

**Denominators:** 216 places use parcel counts scaled to ACS (`parcels_scaled_acs`), 234 use the ACS
single-family fallback; 437 of 450 denominators are flagged low quality.

**Known data caveats (#210):** ADU scale factors far from 1 for Bladen County unincorporated (37017, 0.42),
Union County unincorporated (37179, 0.46), Troutman (3768500, 2.50) and Princeville (3753840, 2.13). Their
contributions here are small (mean added permits 0.6, 45.8, 4.6 and 0.2), so they do not drive the state total,
though Union's 46 is among the larger county figures.

## 4. Fee scenario

PR #189 is merged, so this ran: `uv run python scripts/dev/fee_dev_run.py --state NC`. Only **Raleigh** has
coded fees in `config/fees` for NC (Charlotte is left out as a holdout), so this is a one-city check, not a

|---|---:|---:|---:|---|---:|

## What broke, and what to look at

Nothing crashed and no warnings were printed. No code or data was changed. Points for Ben:

1. **The state ADU law is after the origin.** Every large NC city carries "scheduled after origin:
   NC-SL2026-59" (S.L. 2026-59, ADUs by right in cities of 50,000+, effective 2027-01-15). The run uses rules as
   of 2025, so for 2027–2030 the "added by the reform" figures for those cities are measured against a baseline
   that ignores a law already enacted. If the scenario should be read against the law, their added ADUs shrink
   toward 0. This is a scenario-design question for WS-ENGINE, not a bug.
2. **Charlotte and Mecklenburg are missing from the statewide baseline** (holdout histories end in 2022). Any
   NC state total built from this baseline needs either a held-out-safe level for them or an explicit note.
3. **The ADU result for NC is almost all extrapolation and drawn rules** (440 of 450 outside calibration; 97%
   of parcels on drawn rules). Coding more local ADU rules (the ordinance pipeline) is the main lever.
4. **Fees: Raleigh only, and no new-home value**, so the feasibility channel didn't run.
5. Single-family baseline under-forecast after 2022 persists in NC (all windows), as in D-007.

## Reproduce

```bash
uv run python -m lotline.model.backtest --state NC --spec B
uv run python scripts/dev/adu_dev_run.py --state NC --out <scratch>.csv
uv run python scripts/dev/fee_dev_run.py --state NC --out <scratch>.csv
```

The section 2 baseline figures sum `lotline.model.baseline.forecast_draws` over the four size classes for
`panels.load("NC", store, theme="adu", rule_version=eligible.RULE_VERSION)` at origin 2025, per draw, then take
quantiles (draws share calendar years across size classes, D-030).
